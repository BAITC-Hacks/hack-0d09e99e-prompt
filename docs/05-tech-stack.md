# Технологический стек

## Web ✅ (подтверждено)

| Слой | Технология | Зачем |
|---|---|---|
| Frontend | **Next.js (App Router) + TypeScript** | Быстрый старт, роутинг из коробки, деплой на Vercel за минуту |
| UI-kit | **Tailwind CSS + shadcn/ui** | Красивые enterprise-компоненты: таблицы, бейджи, drawer, modal |
| Таблицы | TanStack Table | Группировка по поставщикам, раскрывающиеся строки с обоснованием |
| Графики | Recharts | История продаж, прогноз с доверительной полосой, сезонность |
| Backend | **Python + FastAPI** | REST API + движок расчёта заказов |
| Расчёты | pandas / numpy / statsmodels | Сезонность, тренд, IQR-выбросы, компенсация stockout |
| Данные | Реальные выгрузки IEK (6 × `.xlsx` из 1С) → pandas | Путь: `IEK_DATA_DIR` = `/Users/azamatomirtaj/Documents/IEK`. Схема — `docs/06-datasets.md`. Синтетику не используем |

## Mobile ✅ (Flutter — согласование, не копия сайта)

Один человек на мобилку уже есть → остаёмся на Flutter. Expo/PWA не плодим.

| Слой | Технология |
|---|---|
| Framework | **Flutter (Material 3)** |
| State | flutter_riverpod |
| Сеть | dio — **тот же REST**, что и веб |
| Графики | fl_chart только мини-график на карточке SKU |
| Пуши | firebase_messaging (демо: локальный/мок пуш на экране) |
| UI | те же токены срочности, что на сайте |

На мобилке **нет**: таблиц, inline-правки qty, экспорта в 1С, кнопки «Пересчитать».
Есть: риски, пуш, утверждение / возврат с комментарием, короткий LLM-чат.

## Архитектура (кратко)

```
/Documents/IEK/*.xlsx
  Динамика продаж          → выбросы / разовые накладные
  Ежемесячные продажи      → спрос, тренд, SKU-сезонность
  Ежемесячные остатки      → stock + stockout (пустые месяцы)
  Путь ИЭК                 → in-transit + ETA
  MOQ ИЭК                  → округление до мин. партии
  Сезонность ИЭК           → бренд-коэффициент
            │
            ▼
     FastAPI + pandas (движок расчёта)
            │ REST / JSON
   ┌────────┴────────┐
Next.js web          Flutter
рабочее место        согласование
таблицы, водопад,    главная рисков,
аномалии, экспорт 1С пуш, утвердить/вернуть
```

Статус заказа общий: `draft → pending_approval → approved | returned`.
Экспорт в 1С доступен только из веба при `approved`.

## Ограничения из кейса (не забыть)

- ❌ Заказ НИКОГДА не уходит поставщику автоматически — только после подтверждения
  сотрудником (confirmation modal в вебе, dialog в мобилке).
- ❌ Неанонимизированные данные клиентов в расчётах не используем (только обезличенные ID).
- ✅ Объяснимость каждой строки рекомендации — обязательна.
- ✅ Экспорт в формате, совместимом с 1С (Excel/CSV).
